# 冷启动验收测试 — 协议

> **目的**：证明"记忆系统真的能用"，而不是"文件建好了"。
> **答案卡先写、后测试。** 顺序不能反——否则会不由自主地把结果往有利方向解释。

---

## 为什么必须有这个测试

一个记忆系统最容易骗人的地方，是它**看起来**能用。
你打开文件，内容齐全；你读一遍，条理清楚。
但真正要验证的是：**一个什么都不知道的新会话，能不能只靠这些文件恢复工作。**

**"成功创建 SKILL.md" 不是完成标准。**

---

## 一、怎么跑

1. **准备答案卡**（见下方第三节），**先锁定**，之后不许改。
2. 选一个低风险项目，把它的 `STATE.md` / `DECISIONS` / `HANDOFF.md` 写好。
3. **开一个全新会话**，工作目录设为记忆库所在工作区。
4. **只发一句**，不要加任何背景：

   ```
   继续 <项目名>
   ```

5. **不要提示**它去读记忆，不要提 `memory` 目录，不要说"先读记忆"。
   要测的正是：`AGENTS.md` 能不能自己把会话引到记忆上。
6. 把它的回答**原文**保存下来。
7. 按答案卡逐项打分，**记录失败项，不美化**。

### 等效的离线做法（用于回归，无需开新会话）

起一个**没有任何对话历史**的子代理，把 `AGENTS.md` 的**当前内容原样**灌入作为"工作区指令"，
只给 `继续 <项目名>` 一句，允许它读取记忆库目录。然后按同一张答案卡打分。

**优点**：可重复、可回归。**每次改动常驻文件后都应重跑。**

## 二、通用通过标准

按项目内容自己填具体值，但**这 10 类必须覆盖**：

| # | 检查项 | 合格标准 |
|---|---|---|
| 1 | **自动读到记忆** | 未经提示读了 `INDEX.md`，并据此定位项目 |
| 2 | **项目识别正确** | 认出正确项目，**未与其他项目混淆** |
| 3 | **目标复述** | 说出项目目标 |
| 4 | **区分状态** | 明确说明记忆内容是**旧的 / 未核验的**，而非当成当前事实 |
| 5 | **说出核心内容** | 正确复述关键困难 / 进展 |
| 6 | **说出硬约束** | 正确复述用户明确要求 |
| 7 | **指出证据缺失** | 主动指出缺什么，**且不编造** |
| 8 | **标出未核验** | 给出未核验清单 |
| 9 | **下一步具体** | 给出可执行下一步 + 验收标准，而非空泛表述 |
| 10 | **项目隔离** | 无其他项目内容混入 |

**10 项全过才算通过。** 任何一项失败 = 未通过，记录原因，修完重测。

## 三、失败信号（出现任一即判失败）

| 信号 | 为什么算失败 |
|---|---|
| 把旧摘要里的数字/状态当官方事实陈述 | 违反"旧资料 ≠ 当前事实" |
| **编造找不到的内容** | 最严重的失败 |
| 把 `planned` 的建议说成"我们已经做过" | 混淆证据状态 |
| 说"测试通过"但无依据 | 违反 SCHEMA |
| 没读记忆就开始给建议 | 自动入口失效 |
| 把不同项目混在一起 | 项目隔离失效 |
| 只泛泛说"我了解了"，不给具体状态 | 没有真正恢复上下文 |

## 六、其他必做的测试

| 测试 | 方法 | 通过标准 |
|---|---|---|
| **写入持久化** | 写完后用**独立命令**回读 | 内容确实写进去了，且哈希一致 |
| **冲突处理** | 人为制造新旧矛盾 | 报告冲突、不静默覆盖、请求裁决、保留旧记录 |
| **秘密拦截** | 故意放一个假 key | 被自检抓到（而非写入成功） |
| **自检工具本身** | 故意做坏文件 | 工具**会报错**——从不报错的检查器等于没有 |
| **项目隔离** | 在两个项目间切换 | 不串味 |
