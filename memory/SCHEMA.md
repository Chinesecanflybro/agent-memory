# SCHEMA — 证据标记与写入规则

> **用途：写记忆之前读这个文件。** 它不在常驻上下文里（常驻只有 `AGENTS.md` + `INDEX.md`）。

---

## 1. 五态标签（每条"做完了什么"必须标其一）

| 标签 | 含义 | 允许的依据 |
|---|---|---|
| `planned` | 决定了要做，**还没动手** | 用户明确要求或书面计划 |
| `changed` | 文件/代码**确实被修改了** | 实际文件差异 |
| `ran` | **确实被执行了** | 命令回执、退出码、运行日志 |
| `test-passed` | **测试真的通过了** | 测试命令的退出码与输出 |
| `independently-verified` | **执行者之外的第三方验证通过** | 独立复现结果 |
| `unknown` | 未核验 | 不要猜 |

**硬规则**

1. **没有 `evidence:` 指向，不许标 `test-passed` 或 `independently-verified`。**
2. **`ran` ≠ `test-passed`。** 跑过但报错，只能写 `ran` + 失败结果。
3. **`planned` 绝不能写成 `changed`。**
4. **禁止用静态阅读代码冒充 `test-passed`。**
5. **历史 PASS 数字不能替代重新运行。**
6. 未核验一律 `unknown`。

## 2. 来源标签（每条事实说清"凭什么"）

| `source` | 含义 | 可信度 |
|---|---|---|
| `user-explicit` | 用户明确说过 | 高（最高权威） |
| `file-observed` | 直接在当前文件中看到 | 高 |
| `test-run` | 实际运行测试得到 | 高 |
| `derived` | 由上述证据推导 | 中，须标推导链 |
| `legacy-summary` | 旧摘要 / 旧交接包 / 历史快照 | **低，仅作导航** |

- `legacy-summary` **永不自动升格**为当前事实。
- 路径、版本号、完成状态**必须**复核后才能写成 `file-observed` 或 `test-run`。

## 3. 写法

**推荐：两个标记分开写**（不易漏）。

```markdown
- 运行 `npm test`，退出码 0，62 项通过。`[status: test-passed]` `[source: test-run]`
```

**也接受合并写**，但**两个键都必须有**：`[status: ran | source: test-run]`

⚠️ **常见错误：只写一个。** 状态与来源是两件事，缺一个即格式错误，自检会报。
- `[status: …]` 答"**做到哪一步**"
- `[source: …]` 答"**凭什么这么说**"

**证据位置写成独立一行**（不是标记的一部分）：

```markdown
  evidence: memory/evidence\2026-10-09-npm-test.log
```

⚠️ **别把来源词写进 status 位**（曾发生过：`[status: derived | source: derived]` — `derived` 是来源词）。

## 4. 项目 STATE.md 必填 frontmatter

```yaml
---
project: <slug>
title: <标题>
status: active | paused | completed | archived
updated_at: 2026-10-10T00:00:00+08:00
root: <真实绝对路径，没有写 null>
source_of_truth: <哪个文件/命令是权威依据>
---
```

建议正文含：目标 · 已确认状态 · 未完成/阻塞 · 硬约束 · 待核验 · 下一步+验收标准 · 变更记录。

## 5. 写入流程

```
1 定位 → 哪个项目？不确定就问用户，不要猜
2 核验 → 路径用 Test-Path、版本用实际命令、完成状态用实际运行结果确认
3 写入 → 按本文件字段与标记写
4 回读 → 用独立命令重新读一遍确认
5 自检 → python memory/tools\memory-check.py   (退出码 0 才算干净)
6 报告 → 改了什么、依据是什么、什么还没验证
```

**第 4、5 步不可跳过。**

## 6. 冲突处理（永不静默覆盖）

```
1 不改、不删旧记录
2 在 events\ 追加一条冲突事件
3 在项目 STATE.md 写「待核验」区块，两侧来源与时间都保留
4 报告用户，请求裁决
5 裁决后：写新记录 + 给旧记录标 superseded_by
```

**裁决优先级**：用户最新明确表达 ＞ 当前实际文件与可复现测试 ＞ 正式项目状态 ＞ 旧摘要。

**严禁**把矛盾说法"合并"成一个看似合理的版本——**那是编造**。

## 7. 交接包（`projects\<项目>\HANDOFF.md`）

必含：当前目标 · 已确认状态（逐条带 `status`+`source`）· 已完成/未完成 · 硬约束与被替代的旧决定 ·
**真实**路径与版本 · **证据位置** · **已尝试但失败的方法**（避免重复踩坑）· 未解决问题 ·
下一步+验收标准 · 明确的未核验清单。

**禁止**含任何 API Key / 密码 / token / cookie。

## 8. 项目隔离

不同项目分开存放，互不引用对方状态。课程、科研、软件、个人规划不得混在同一文件。
无法确定项目时**先问，不要猜**。

## 9. 安全禁令

**永不写入**：API Key、访问令牌、密码、cookie、私钥；`<path>` 的任何内容。

⚠️ 该文件含明文 API Key → **任何导出记忆/交接包的操作必须显式排除整个 `$DSH_HOME`**。

## 10. 并发的写法要求

同一工作区可能有多个会话同时运行。**先读后写、写后回读**；发现他人已写内容 → **追加补充，不要覆盖**。
