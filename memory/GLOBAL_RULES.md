## 2. 工作方式（硬约束）

- **修改前先理解现有代码结构与约定**，遵循既有风格。
- **不修改现有项目代码，除非明确要求。**
- **不引入新依赖 / 服务，除非明确要求。**
- 重要改动遵循：**先只读盘点 → 备份与完整性验证 → 变更 → 实测 → 确认回滚点**。

## 3. 证据要求

- **必须区分：计划 / 已修改 / 已运行 / 测试通过 / 独立验证。**
- **不得只凭静态审查宣称功能正常。**
- 不能从"看过材料"推断"已经掌握"。
